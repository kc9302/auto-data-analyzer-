# [정책서] 자동 데이터 분석 모듈 - 개발 원칙 및 보안/운영 정책
- **문서 버전:** v1.0.0
- **작성 주체:** 특급 기획자 & 특급 시스템 아키텍트 공동 수립
- **적용 대상:** `auto-data-analyzer` 전체 모듈 및 파이프라인

---

## 1. 핵심 개발 철학 (Andrej Karpathy 원칙 계승)

1. **Think Before Coding (선 기획, 후 구현)**
   - 요구사항과 엣지 케이스(대용량 테이블, 비정형 데이터, 혼합 타입)를 사전에 정의하고 설계 합의 후 코드를 작성한다.
2. **Simplicity First (최소 실행 가능 설계)**
   - 불필요하게 거대한 프레임워크나 오버엔지니어링을 배제하고, 핵심 목적(DB 프로파일링 -> EDA -> 최적 ML 추천/학습)에 집중된 직관적인 코드로 작성한다.
3. **Surgical & Modular (격리된 모듈화)**
   - 커넥터(Connectors), 프로파일러(Profiler), 분석기(Analyzer), ML엔진(Engine), 리포터(Reporter)를 엄격히 분리하여 독립적인 단위 테스트와 확장이 가능하게 한다.
4. **Goal-Driven Execution (검증 가능한 결과)**
   - 모든 단계는 모의 DB(SQLite / Mock DB) 및 표준 벤치마크 데이터셋 기반의 테스트 코드로 동작을 증명한다.

## 2. 데이터베이스 보안 및 안전 정책 (Source DB Zero-Impact)

어떤 DB든 접속 정보가 입력되었을 때, 대상 DB의 안정성을 해치거나 데이터를 변조하는 사고를 원천 차단한다.

### 2.1 절대적 읽기 전용 (Zero Mutation)
- **원칙:** 대상 DB에 대한 `INSERT`, `UPDATE`, `DELETE`, `DROP`, `ALTER`, `CREATE` 등 어떠한 쓰기 쿼리도 전송하지 않는다.
- **구현 방식:**
  - DB 커넥션 생성 시 드라이버 레벨에서 `READ ONLY` 트랜잭션/세션 모드를 강제 활성화.
  - SQL 실행 엔진에서 DDL/DML 차단 인터셉터 적용 (오직 `SELECT` 및 메타데이터 딕셔너리 조회만 허용).

### 2.2 부하 제어 및 대용량 안전장치 (Anti-OOM & Throttling)
- **전체 풀스캔 금지:**
  - 프로파일링 시 `SELECT * FROM table`을 메모리로 한 번에 불러오지 않는다.
- **적응형 샘플링 (Adaptive Sampling):**
  - 테이블 메타데이터의 `Row Count`를 먼저 확인.
  - 소형 테이블 (< 50,000행): 전체 프로파일링.
  - 중/대형 테이블 (≥ 50,000행): 통계적 신뢰수준 99%, 오차범위 1% 수준의 무작위/계통 샘플링(최대 50,000행) 추출.
- **쿼리 타임아웃 및 동시성 제한:**
  - 단일 쿼리 최대 실행 시간 제한 (기본 30초). 타임아웃 발생 시 즉시 취소 및 오류 로깅.
  - 동시 커넥션 풀 크기 최소화 (Default: 2~4)로 대상 DB 리소스 점유 방지.

### 2.3 개인정보 및 민감 데이터 보호 (PII Masking)
- **민감 정보 자동 감지:**
  - 컬럼명 휴리스틱 (예: `password`, `ssn`, `resident_no`, `card`, `email`, `phone`, `token` 등).
  - 데이터 정규식(Regex) 및 엔트로피 분석을 통한 주민번호, 신용카드, 계좌번호 패턴 탐지.
- **마스킹 및 학습 제외:**
  - 탐지된 PII 컬럼은 프로파일링 결과에서 마스킹(`***`) 처리하며, ML 모델의 피처 후보에서 자동 제외.

## 3. 머신러닝 추천 및 학습 정책 (AutoML Governance)

### 3.1 문제 유형 자동 판별 기준
1. **타겟 컬럼(Target) 지정 시:**
   - 고유값 비율 및 데이터 타입 기반:
     - 카테고리/문자열 또는 정수형 고유값 적음 -> **분류(Classification)** (이진 / 다중)
     - 연속형 실수값 -> **회귀(Regression)**
     - 날짜/시간 인덱스 + 연속형 변수 -> **시계열 예측(Time-series Forecasting)**
2. **타겟 컬럼 미지정 시 (비지도 학습 모드):**
   - 데이터 그룹핑 및 세분화 -> **군집화 (K-Means, HDBSCAN)**
   - 이상 거래/비정상 패턴 탐지 -> **이상치 탐지 (Isolation Forest, LOF)**

### 3.2 리소스 및 시간 예산(Time-Budget) 정책
- **경량 모델 우선 원칙:**
  - 무거운 딥러닝 모델 이전에 정형 데이터의 표준인 **LightGBM, XGBoost, CatBoost, Scikit-Learn** 기반의 고속 트리 모델을 우선 검증.
- **Time-Budget 강제:**
  - 사용자가 설정한 탐색 시간(예: 기본 3분 / 5분) 내에서 최적 하이퍼파라미터 및 모델 탐색 완료.

## 4. 최종 산출물 및 인터페이스 정책
- **독립 실행형 결과물:**
  - `report.html`: 설치 없이 브라우저에서 열람 가능한 시각화 대시보드(차트, 통계표, 모델 설명력 SHAP).
  - `model.joblib` or `model.onnx`: 즉시 추론(Inference)에 사용할 수 있는 경량 모델 아티팩트.
  - `pipeline.py`: 데이터 전처리부터 모델 서빙까지 재현 가능한 파이썬 파이프라인 코드.
